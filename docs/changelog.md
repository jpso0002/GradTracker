### Added

- **2026-08-18** — **T5.1 design system integration.** The system is vendored into `packages/client/src/ds/vendor/` by `scripts/sync-ds.mjs` rather than imported: it lives at the repository root, outside every package, in a folder whose name contains a space. A copy nobody checks is a copy that rots, so `ds.sync.test.ts` fails on any byte of drift — the same guard the two schema dialects use. `src/ds/index.ts` re-exports and nothing else; no component is wrapped or restyled. Theme is a `data-theme` attribute on `<html>` and nothing more, because the design system defines both palettes and the app's only job is to pick one. `no-hardcoded-colour.test.ts` sweeps every source file outside `vendor/` for hex, `rgb()`, `hsl()` and named colours, and asserts it found source to check so an empty sweep cannot pass vacuously. · `packages/client/src/ds/**`, `packages/client/scripts/sync-ds.mjs`
- **2026-08-18** — **T5.2 app shell and routing.** 240px sidebar, routes per app-flow.md §1.1, and a `ToastHost` so no view owns a corner of the screen. `/pipeline/:jobId` is a route, not component state, so an application is bookmarkable and browser-back closes the panel instead of leaving the pipeline. Calendar and Archive are in the sidebar and lead to a view that says no design exists yet — blank means blank (design.md §9); a plausible-looking placeholder reads as a broken feature rather than an unbuilt one. · `packages/client/src/{App.tsx,shell/**,views/BlankView.tsx}`
- **2026-08-18** — **T5.3 typed API client.** Every response type is inferred from a shared Zod schema and **parsed** at runtime, not cast — an unexpected payload fails next to the request rather than three components deep as `undefined is not an object`. `NetworkError` is a distinct class from `ApiError` because "could not reach the server" and "the server said no" are different situations with different remedies and different surfaces. The browser's IANA timezone goes out on every request, resolved per-request because a student can cross a timezone. · `packages/client/src/api/client.ts`
- **2026-08-18** — **T5.5 pipeline view.** Four stat cards, Active/Archived tabs, six stage filter chips, and the ranked row list. The client never re-sorts: a test feeds a deliberately non-alphabetical, non-date order and asserts the DOM preserves it, so any client-side sort fails loudly. Filters go to the server, which re-ranks; there is no `?sort=` control, because a student who can sort by company name has rebuilt the spreadsheet this replaces. Counts render as **—** until known — "0 due this week" is a claim, "not loaded yet" is not — and an empty pipeline is distinguishable from filters that are merely too narrow. Loading is a row-shaped skeleton, not a spinner: the list has a known shape, so show that shape. · `packages/client/src/views/PipelineView.tsx`
- **2026-08-18** — **T5.6 detail panel.** Company, role, stage, extracted fields with provenance, event timeline, withdraw. The timeline links to `rfc822msgid:` in Gmail rather than showing content — GradTracker stores no subject or body, so sending the student to their own inbox is the only honest way to show a source (SM-6). Each event shows the company and role that email itself claimed (T4.8), which is what lets the timeline say "this email said KPMG" beside a job the student later renamed. · `packages/client/src/views/DetailPanel.tsx`
- **2026-08-18** — Icons bundled from npm instead of the CDN. The design system's `Icon` fetches `unpkg.com/lucide` when `window.lucide` is missing; `src/ds/icons.ts` populates it first, so the app needs no network to draw its own chrome — which matters for a product that ships an offline banner. Only the ~32 referenced glyphs are bundled rather than all 2,021, taking the bundle from 716 kB to 330 kB, and `icons.test.ts` walks the source for every icon name in both the app and the vendored components so trimming the set cannot produce a blank square. Verified in the failing direction. · `packages/client/src/ds/{icons.ts,icons.test.ts}`

- **2026-08-18** — **T4.5 review routes.** `GET /api/review`, `POST /api/review/:id/confirm`, `POST /api/review/:id/dismiss`. Dismissal marks the row, never deletes it: the `(user_id, gmail_message_id)` unique constraint is what guarantees a re-sync cannot resurrect a rejected email. · `packages/server/src/routes/review.ts`
